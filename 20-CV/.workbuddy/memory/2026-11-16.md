**技术选型讨论**：用户问工业上怎么起服务、标准库是否更难维护。结论：工业是
FastAPI/Flask + uvicorn/gunicorn + Nginx + systemd/Docker，加载大模型的服务建议
`workers=1`（多 worker 会各加载一份模型）；标准库在小工具省事，接口一多就要手写
路由/解析/静态文件/并发，维护成本陡增。本机 fastapi/uvicorn 已装 → 改用 FastAPI。
另说明「封装 Web 工具确实提升调试效率，但 week-02 批量回归与 mvp 单文件预览定位互补；
自包含复制存在逻辑漂移风险，稳定后应抽公共模块（届时需动 week，另行确认）」。

upload.html,upload.css,upload.js}`。源码 CSS/JS 是独立文件，`builder` 生成报告时
