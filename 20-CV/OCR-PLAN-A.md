## 1. 学习方法与心法

最大的风险不是"学不会"，而是**"只看视频不动手"**和**"卡在数学上出不来"**。守住这几条：

1. **先跑通，再理解（top-down）。** 每个新概念先照抄代码跑出结果，看到图/框/loss 下降，再回头懂原理。CV 的好处是**结果肉眼可见**——用可视化建立直觉。
2. **每个概念配一段最小代码。** 学"卷积"就手写跑一次卷积；学"反向传播"就用 numpy 手推一次。不动手 = 没学。
3. **数学 just-in-time。** 缺的数学（矩阵乘法、梯度、链式法则）边学边补，别花一个月单独啃高数。概率统计你已有（特征工程）。
4. **每阶段产出一个"能拿出手的小项目"。** 没有产出的学习不算数。
5. **卡住超过 2 小时就跳过/求助。** 先标记、继续推进、回头再补，别原地消耗。
6. **用 AI 当私教，不当拐杖。** 让 AI 解释概念、review 代码、出练习题；但训练循环、模型结构要自己手敲一遍。

### Vibe Coding 黄金法则（Java 背景专属）
- ✅ **适合交给 AI**：写 OpenCV 预处理、生成数据增强脚本、写 Dockerfile、解释报错。
- ⚠️ **必须你自己懂**：选模型架构、设计损失函数、诊断"为什么不收敛"。AI 是代码生成器，**绝不能做架构决策者**——不懂底层，AI 生成的代码往往"能跑但效果差"。

## 2. 数学到底要学多深（预期管理）

**结论：整条路线需要「高中 + 大一」数学，全程 just-in-time 补。** 框架（PyTorch）封装了计算，你要的是**理解原理**，不是手推公式。

| 阶段 | 用到的数学 | 要求 | 说明 |
|---|---|---|---|
| P1 | 导数、梯度、链式法则、矩阵运算 | ⭐⭐ 中低 | 懂"梯度=下降最快方向""卷积=滑动窗口矩阵乘法"；numpy 手推一次是为理解，不是考试 |
| P2 | 概率、IoU、softmax | ⭐⭐ 中低 | 懂"softmax 转概率""IoU 卡检测框"即可 |
| P3 | 概率、softmax、LSTM 门控 | ⭐⭐⭐ 中 | LSTM 门控公式多但**不需手推**；理解"加权求和"的注意力直觉 |
| **P4** | **动态规划（CTC）** | ⭐⭐⭐⭐ 较高 | **本路线最难的数学**，但有 Distill 可视化辅助，**理解原理即可，不用手推前向-后向算法** |
| P5 | 量化数值（FP16/INT8） | ⭐ 低 | 工程概念，无推导 |

> **CTC 是唯一的"高门槛"点**，但它有极好的可视化资源（见资源表）。你不需要会推公式，只要能回答："输入特征序列和输出文字序列长度不对齐，CTC 怎么算损失？"——理解这句话就够用。

## 8. P3 · 序列建模 + Transformer（周19-22）

> **载具版整块跳过了这一章，本完整版必须学**——因为文字识别（把图转成有序字符串）离不开序列建模。

### 周19-20 · RNN / LSTM
- [ ] **为什么需要序列建模**：文字是有序的（"cat" ≠ "tac"）
- [ ] RNN 原理：隐藏状态、时间步、梯度消失
- [ ] LSTM：门控机制解决梯度消失（**门控公式多，不需手推，理解"门"的直觉即可**）
- [ ] PyTorch RNN 教程跑一遍
- [ ] **里程碑**：能解释 RNN 如何处理序列、LSTM 为什么能缓解梯度消失

### 周21-22 · 注意力 + Transformer
- [ ] **Attention 核心思想**：不是所有输入都同等重要，让模型学会"关注哪里"（理解"加权求和"）
- [ ] Seq2Seq + Attention：编码器-解码器架构
- [ ] Transformer 入门：用自注意力替代 RNN，并行计算
- [ ] 👁️ 看 [The Illustrated Transformer](https://jalammar.github.io/illustrated-transformer/)（可视化，强烈推荐）
- [ ] **ViT（Vision Transformer）**：知道它把图像切 patch 当序列处理即可
- [ ] **里程碑**：看到 CRNN 的"CNN + RNN + CTC"结构能说出每部分作用；理解 Attention 的加权求和机制

> ⚠️ **区分**：本章要学的是"序列建模 + 注意力"（OCR 识别必需）；不必深入的是 Transformer 的每一个数学细节（懂原理、能读结构图即可）。

## 9. P4 · OCR 核心技术（周23-30）

> 掌握文字检测 + 文字识别两大核心，跑通端到端 OCR 流水线。这是本计划的重头戏。

### 周23-25 · 文字检测（Text Detection）
- [ ] 任务：找到图像中文字的位置（= 目标检测的特例）
- [ ] **EAST**：简单高效，适合场景文字
- [ ] **DBNet**：基于可微二值化的分割方法，工业界常用
  - 理解"可微二值化"：把分割概率图转成二值掩码，且可端到端训练
  - 后处理：二值化/连通域/多边形
  - 文字区域表示：四边形 box vs 像素级掩码
- [ ] 读 [DBNet 论文解读](https://arxiv.org/abs/1911.08947) + PaddleOCR 检测模块文档
- [ ] **在工作数据或 ICDAR/公开集上微调检测头**
- [ ] **里程碑**：能讲清 DBNet 流程，微调过检测头，练过小目标/密集目标后处理

### 周26-28 · 文字识别（Text Recognition）
- [ ] 任务：把文字图像转成文本字符串
- [ ] **CRNN**：CNN（特征提取）+ RNN（序列建模）+ CTC（对齐），经典 baseline
- [ ] **CTC Loss（本章最难）**：解决输入特征序列与输出文字序列长度不对齐
  - 先看 [Distill CTC 可视化详解](https://distill.pub/2017/ctc/)
  - 理解核心问题即可，**不用手推前向-后向算法**
- [ ] **SVTR**：基于 Transformer 的识别器，SOTA（了解）

## 11. PaddleOCR 掌握程度分层 L1-L4

> 用来定位"我现在在哪、要学到哪"。**80% 工作场景 L1-L2 就够。**

| 等级 | 能力 | 对应阶段 | 具体表现 |
|---|---|---|---|
| **L1 会用** | 跑通工具、得到结果 | P0 结束 | 装好 PaddleOCR，跑通检测+识别 demo，标准场景输出可用文字 |
| **L2 会调** | 效果不好知道怎么救 | P4 结束 | 会微调、数据增强、bad case 归因；知道是数据问题还是模型问题，知道调哪些参数 |
| **L3 会改** | 改源码/结构适配业务 | P4+P5 项目后 | 能替换 backbone、改后处理（调 DBNet 阈值）、定制字典、裁剪模型部署到边缘 |
| **L4 会造** | 从零设计模型 | 需更多研究积累 | 针对特殊场景（手写/艺术字/表格）设计新结构、发论文 |

> **类比**：P0 结束 = 会开车（能到目的地，坏了送修）；P4 结束 = 会修车（异响在哪、换什么零件自己搞定）。

## 14. 三条护栏

1. **不跳基础直接调包。** PaddleOCR 很好用，但不懂 CNN/检测/CTC 原理，遇到 bad case 就抓瞎。P1/P2 地基不能砍。
2. **图像思维 ≠ 表格思维。** 表格是"一行一个样本"，图像是"一个 H×W×C 矩阵"。别用 Pandas 思维处理图像。
3. **每个难点先自检一句**：这是**OCR 核心能力**（检测/识别/部署）还是**兔子洞**（手写体/生僻字/文档语义）？只深入前者，后者够用即可。
