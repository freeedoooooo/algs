## 咨询：入库数据的血缘回溯方案（未立项，仅设计建议）
- 用户问：预览已有逐格血缘（c1_staging_lineage），入库后如何回溯；业内主流怎么做。
- 现状盘点：预览血缘 = c1_staging_lineage（record_id+field_name+page+cell_bbox+raw_text）；入库回执 = c1_load_log（task_file_id+record_index+datasource_id+target_table+target_pk+action），二者靠 (task_file_id, record_index) 软连接；loader.write_record 的 pk 在 insert 时是 lastrowid、upsert 时是业务键 JSON。
- 建议（分层，均未实现）：①回执扩为不可变证据包，写入时冻结 rule_version_id / 映射快照 hash / transform 版本 / 写入值 hash / before-after / 单元格快照；②业务行加稳定身份 _c1_row_uid（可选列，对标 Iceberg V3 _row_id）；③回执哈希链做 tamper-evident；④运行级 OpenLineage RunEvent（Marquez/DataHub 消费）与记录级证据链分离。
- 关键坑：现有 uk_load_receipt 幂等唯一键 skip 会吞掉血缘更新；重抽按 task_file 先删后插会让 record_index 复用导致血缘漂移；入库目标禁选平台 c1_* 表（既有警示）。
- 业内结论：目录型（OpenLineage/DataHub/Atlas/Unity Catalog）止于 dataset/column 级；record 级 provenance 需自建（W3C PROV 词汇层 + 写入时采集），Iceberg V3 才有原生 row lineage；QLDB 已于 2025-07-31 退役。

## 追加：业务表统一带 taskId 的简化方案评估（同日）
- 用户提出：biz 业务表统一加 taskId，能否从业务行反查 task。结论：可行且成本最低，但只打通"业务行→task"第一跳；task→task_file→staging_record 是 1:N:N，单行无法定位具体暂存记录。
- 最小补丁：业务表再加 record_ref（=staging_record.id 或 task_file_id+record_index），形成 业务行→(task_id,record_ref)→staging_record→staging_lineage→单元格；两列均为系统列，不进规则字段映射。
- 三个工程点：①upsert 下 taskId 是"最近写入者"语义（write_record 覆盖非业务键列），完整来源史留 c1_load_log；②系统列注入走 loader 新参数 extra_values + preflight 检查目标列，不污染 validate_fields；③回执存 value_hash，回溯时比对当前行检测下游改写。
- 前提风险：存量回填依赖 target_pk（insert=lastrowid 可回填，upsert=业务键 JSON 需按列匹配）；已 loaded 任务的 staging/原件不得清理（run_extract 已禁对 loading/loaded 重抽）；对外宜用稳定 task_public_ref 而非裸自增 id。
- 仍未立项、未改代码；若落地建议独占窗口，因为动入库主链路。

## 追加：平台业务无关 + 项目概念打通的分层方案（同日）
- 用户新思路：①业务侧中间表把项目/项目附件映射到 taskId；②业务表统一带 taskId（禁止 projectId 以保持平台业务无关）+ recordId。
- 评估结论：可行，但两件事正交——中间表解决"业务概念打通/归属查询"；taskId+recordId 解决"行级反向回溯"。业务无关性成立的关键：中间表放业务侧、平台只认 taskId/recordId 两个裸 ID，不引入 project 语义。
- 关键约束：recordId 必须=平台 staging_record.id（或稳定 record_ref），若是业务表自增主键则回溯断链；taskId 用稳定外部引用（task_public_ref）而非裸自增 id 更抗迁移。
- 粒度提醒：attachment 对应平台 c1_task_file 而非 task（task 可含多文件）；中间表可建 project↔task 与 attachment↔task_file 两张，或只建后者再上卷。
- 三个前提：loaded 任务 staging/lineage/原件不清理；按 task 冻结字段映射快照（否则映射改后回溯错）；taskId/recordId 走系统列注入不参与 upsert 业务键。
- 仍未解决：upsert 最近写入者语义、存量回填、跨环境 ID 稳定性。未改代码。
