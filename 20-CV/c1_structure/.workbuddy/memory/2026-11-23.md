## 追加：业务表统一带 taskId 的简化方案评估（同日）
- 用户提出：biz 业务表统一加 taskId，能否从业务行反查 task。结论：可行且成本最低，但只打通"业务行→task"第一跳；task→task_file→staging_record 是 1:N:N，单行无法定位具体暂存记录。
- 最小补丁：业务表再加 record_ref（=staging_record.id 或 task_file_id+record_index），形成 业务行→(task_id,record_ref)→staging_record→staging_lineage→单元格；两列均为系统列，不进规则字段映射。

- 前提风险：存量回填依赖 target_pk（insert=lastrowid 可回填，upsert=业务键 JSON 需按列匹配）；已 loaded 任务的 staging/原件不得清理（run_extract 已禁对 loading/loaded 重抽）；对外宜用稳定 task_public_ref 而非裸自增 id。
