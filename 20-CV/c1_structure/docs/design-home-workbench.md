## 一、大白话部分

### 1.1 这是个什么东西

打开平台先看到一张**工作台**：不教你流程，只回答一件事——**"你现在该干嘛"**。

页面从上到下就三块：

```
┌────────────────────────────────────────────────┐
│  ⬇ 快速提取：把文件拖进来（选模板：[自动/模板名 ▾]）│   ← 想直接干活的人，零步数
├──────────────┬──────────────┬──────────────────┤
│ ① 提取        │ ② 校验        │ ③ 入库           │
│ 进行中 2 个    │ 待校验 5 个    │ 待入库 3 个       │   ← 三张状态卡＝流程本身
│ → 查看        │ → 去校验      │ → 去入库          │      数字为 0 时卡片变灰，点进去是空态指引
├──────────────┴──────────────┴──────────────────┤
│ 需要处理的事（只列需要你动手的，最多 8 行）          │
│  #56 · 银行流水11月.csv   ② 还差 4 条未校验  [去校验]│   ← 待办列表＝卡片的展开
│  #55 · 合同扫描件.pdf     ③ 校验完毕待入库   [去入库]│      另有失败/部分入库的提醒行
│  …  全部任务 →                                    │
└────────────────────────────────────────────────┘
```

### 1.2 场景例子

**小王（第一次用）**：同事发他网址，打开就是三张 numbered 卡片＋一句话副标题（① 把文件变成表格记录 · ② 逐条核对改错 · ③ 写进业务库）。他不需要任何人讲解，顺序就写在脸上；什么都不用做时页面显示"暂无待办，拖入文件开始第一次提取"。

**小李（天天用）**：早上打开，②卡上写着「待校验 5 个」，点「去校验」直达校验台并自动带上进度筛选；处理完回来看③卡，点「去入库」直接弹出他熟悉的四步向导。以前他要自己记住"先去任务页找哪个没校验"，现在页面替他记。

### 1.3 为什么不是静态"使用指南"页

上一轮流程条挂到提取/校验页被你撤掉，已经给过答案：**用户不想被教流程，只想被告知下一步**。指南页新人看一次就再也不看，还挡在所有人的入口上；工作台每一块都是"当前状态＋可点动作"，天天用也有价值。流程解释压缩成卡片副标题一句话，够用。

## 二、页面设计细节

### 2.1 数字口径（全部前端可算，见 §四契约）

| 位置 | 口径 | 数据来源 |
|---|---|---|
| ① 提取·进行中 | 任务 state ∈ pending/extracting | /api/tasks |
| ② 校验·待校验 | 文件级 pending_n＋edited_n ＞ 0 的文件数 | /api/staging/ledger |
| ③ 入库·待入库 | task state=previewed 且该任务所有文件 pending_n=0（校验完优先展示；未校验完也可入库，入口在②卡兜底） | 两者结合 |
| 提醒行 | failed / partial 任务；loading 进行中提示 | /api/tasks |
| 待办列表 | ②③的展开，按更新时间新在前，截前 8 行 | 同上 |

### 2.2 交互规则

- 三张卡点击：①→提取页；②→校验台（自动带 `进度=有待校验` 筛选，沿用台账已有下拉）；③→**直接打开第一个待入库任务的入库向导**（wizard.js 已全局挂载；列表>1 时卡片点开的是校验台同款任务清单弹层？不做——见 H2）。
- 快速提取条：拖拽或点击选文件＋模板下拉（复用提取页同一份模板列表逻辑），提交后原地变"已提交，进行中"并可跳任务；不搬提取页的报告区。
- 待办行动作只有两个按钮：`去校验`（跳校验台定位该任务）、`去入库`（开向导）。回执/失败详情仍归任务页，工作台不做第二套详情。
- 数字轮询：沿用 #87 的轻量轮询约定（可见时才轮、只拉计数接口），无新端点。
- 空态：三卡全 0 且无进行中 → 「暂无待办。拖入文件开始，或到 资料页 查看原件」。
- 首次进入不做一次性弹窗引导（会被当广告关掉），卡片副标题就是引导本身。

### 2.3 命名与导航

- 导航顺序改为：**工作台 · 提取 · 资料 · 模板 · 校验 · 入库 · 任务**（全站 7 个 html 一次改齐）。
- 路由：`/`＝工作台（新页 home.html）；`/extract`＝现提取页（upload.html 内容不变，仅换地址）；旧 `/upload` 不存在，无兼容包袱。
- 术语全部沿用已落地口径（业务库/入库规则/去重依据），不引入新名词。"工作台"只出现在导航与页头。

## 三、决策点（实施前需拍板）

- **H1 ③卡跳转方式**：A. 待入库只有 1 个时直接弹向导，多个时跳任务页筛选视图（推荐，简单）；B. 卡片展开内联小列表逐个弹向导（多一层 UI，暂不建议）。
- **H2 待办列表上限**：8 行截断＋"全部任务→"（推荐）vs 与卡片同页再放分页（会和任务页重复，不建议）。
- **H3 快速提取条的模板默认值**：记住上次选择（localStorage，推荐）vs 每次必选（防误用默认模板提错）。
- **H4 路由切换时机**：`/`→工作台需要改 app.py，正好**并入你本来就要做的那次 8765 重启**（推荐，一次重启两件事都生效）；若想先不动后端，可先上 `/home` 观察一轮再切换。

## 四、技术契约（后半页，拍板后照此实施）

### 4.1 新增/改动文件

- 新增 `web/home.html`＋`home.js`＋`home.css`（页面私有样式复用 shell.css token；不引 stage/staging 依赖）。
- `app.py`：`/` 改 `asset('home.html')`；新增 `/extract` → `asset('upload.html')`。仅此两行，无 API 改动。
- 链接审计清单（改 `/`→`/extract` 引用）：shell.js flowbar steps[1]；upload.html 自身 nav；sources/templates/staging/load/tasks 各 nav；staging.js/tasks.js 若有 `href="/"` 返回提取的按钮；wizard.js 提示文案链接。实施时以 grep `href="/"` 为准全数过一遍。

### 4.2 数据来源与口径实现

- 计数纯前端：`GET /api/tasks`（items[].state, files[].state）＋ `GET /api/staging/ledger`（items[].files[].pending_n/edited_n/confirmed_n/rejected_n、records_n）。
- 「校验完待入库」＝ task.state==='previewed' 且 ledger 该任务下所有文件 pending_n===0；rejected 不阻塞（入库时由 gate 处理）。
- 轮询：页面可见时每 5s 只拉以上两个端点（与 #87 节流口径一致），隐藏即停。
- 快速提取复用 `POST /api/tasks`（b64 上传）与 `/api/templates` 下拉，逻辑从 upload.js 抽最小可用部分或复制 30 行（倾向复制，避免把提取页拖进重构）。

### 4.3 红线与边界

- 不动 DB、不动既有 API 契约、不引入身份/权限概念。
- 工作台不复制：筛选器、分页、任务详情抽屉、回执抽屉（保持任务页/校验台唯一实现，UI 一致性令仍然适用）。
- 向导在 `/` 页面可用：home.html 引 wizard.css/js（同 tasks.html 挂法）。
- 回滚：路由两行改回＋导航不动即可，卡片无状态、不落库。

## 五、验收（轻量，按"不卡验证"约定）

- node --check 全部 js；grep 审计 `href="/"` 无漏网。
- 浏览器冒烟：真实数据只读——三卡数字与任务页/校验台台账对得上；②跳带筛选；③按 H1 拍板结果走；快速提取用现有测试文件提一次（走已有 temp 流程，不碰业务库）。
- app.py 两行属路由改动，随你那次统一重启验证；重启前 `/extract` 404 属预期。
