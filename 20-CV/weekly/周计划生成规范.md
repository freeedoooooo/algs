# 周计划生成规范（混合模式）

> 本文件定义"如何把《../OCR学习计划.md》的某个阶段，落地成一个可执行的周目录"。
> 下次生成第 5 周及以后（或工业缺陷计划的周目录）时，**照这份规范来**，保证风格、颗粒度、学习强度一致。

---

## 一、核心理念：混合模式（按"学习价值"分类，不一刀切）

**判据一句话**：*敲这段代码本身能不能学到东西？*

| 类型 | 判据 | 怎么处理 |
|---|---|---|
| **脚手架 / 工具调用** | 敲了学不到深度学习（环境、数据下载、画图、调 API、批量脚本、Docker） | **预先写好、可直接运行**，省下精力给核心 |
| **核心学习代码** | 敲的过程 = 学习本身（前向/反向传播、损失、训练循环、模型结构、梯度推导） | **只给空白练习文件**：函数签名 + TODO + shape 提示，**绝不给答案** |

**为什么**：整个计划的铁律是"动手写代码 ≥60%""不动手=没学"。反向传播这类东西，看十遍不如自己对着 shape 报错调一遍。把答案直接塞给学员 = 帮他跳过唯一有效的那段。

**分界参考**（OCR 计划）：
- P0（第1-2周，用 PaddleOCR）→ 基本全是脚手架，**给可运行脚本**
- P1-A 起（第3周+，手写模型/梯度）→ 核心学习，**给空白练习**
- 但 P1 里的数据加载/画图仍是脚手架 → 抽到 `data_utils.py` 写好

## 二、每周目录布局

```
week-NN/
├── README.md            # 周计划正文（8 段结构，见下）
├── notes.md             # 学员笔记模板（留空让他填）
├── requirements.txt     # 本周依赖
├── data_utils.py        # 脚手架：数据下载/one-hot/画图（P1 起需要）
├── <可运行脚本>.py       # 脚手架类：给出完整可运行代码
└── ex_<主题>.py          # 核心学习类：空白 TODO 练习（ex_ 前缀 = exercise）
```

**命名约定**：
- 练习文件统一 `ex_` 前缀（exercise），一眼区分"这是要我写的"
- 脚本/工具用 ASCII 文件名（避免终端里中文名麻烦），`.md` 可中文
- bad case 等素材目录放在对应周下（如 `week-02/bad_cases/`）

---

## 三、README.md 的固定 8 段结构

每周 README 必须包含（顺序固定）：

1. **抬头引用块**：阶段 / 参考投入 / 前置 / 一句话定位
2. **本周定位**：这周在整条路线的位置 + 🔗 bad case 回看锚点（P1 起每周必有）
3. **本周目标**：一句话 + 3-6 条硬指标
4. **逐日安排**：Day1-5 + 周末 的表格，每天配时长（工作日晚 1-1.5h，周末 4-6h）
5. **学什么 & 怎么学**：分模块（A/B/C…），每块含【概念清单】【怎么学/动手】【可直接抄的代码或 TODO 指引】【产出】
6. **本周资源清单**：所有链接集中成表，点开即用
7. **验收清单**：周末打勾的 checkbox
8. **常见坑 & 卡住怎么办** + **进度日志**（填空模板）

---

## 四、空白练习文件（ex_*.py）的写法规范

必须包含：
- **顶部 ⚠️ 学习规则**：①先自己写、别翻 README 答案 ②卡住 >2h 再看指定资源 ③达标标准
- **函数签名 + docstring**：写清输入输出、shape、思路提示
- **TODO 分步编号**：把一个函数拆成 5a/5b/5c 小步
- **shape 提示**（如 `dW2 应为 (128,10)`）——这是最有价值的脚手架，帮学员自查
- **`raise NotImplementedError`** 占位，逼他填
- **`if __name__ == '__main__'` 运行器**：写好调用顺序 + 目标提示（如"目标准确率 ≥95%"）
- **boilerplate 直接给**：数据加载、one_hot、画图写在文件顶部或 `data_utils.py`，标注"这不是学习重点"

**绝不能出现**：核心函数的完整实现、梯度的最终公式（可给"你在第X周推过，复用"这类指引）。

---

## 五、通用铁律（每周都适用，写进 README）

1. **"本周跑通了什么"不能为空**——只看不写 = 没学
2. **卡住超过 2 小时就跳过/求助**，标记后继续，别原地消耗
3. **先跑通再理解**（top-down）：照抄/跑出结果，再回头懂原理
4. **数学 just-in-time**：遇到再补，别单独啃；懂概念即可，框架封装计算
5. **bad case 回看锚点**：把抽象练习绑定到真实 OCR 问题，防动机断层

## 六、生成新一周的操作步骤（Checklist）

1. 翻《../OCR学习计划.md》找到对应阶段的周计划（如 P1-B 第5-6周）
2. 建目录 `week-05/`，写 `README.md`（严格套 8 段结构）
3. 逐条判断本周每个动手任务属于【脚手架】还是【核心学习】
4. 脚手架 → 写成可运行 `.py`；核心学习 → 写成 `ex_*.py` 空白练习（套第四节规范）
5. 写 `requirements.txt`、`notes.md` 模板；需要则补 `data_utils.py`
6. 资源链接**只放你有把握的真实 URL**；不确定的写"B站搜『关键词』"而非编造链接
7. 更新 `weekly/README.md` 索引表：加一行（周/阶段/主题/里程碑/状态）
8. 自检：练习文件里**有没有泄露答案**？README 里 bad case 锚点、验收清单齐不齐？
