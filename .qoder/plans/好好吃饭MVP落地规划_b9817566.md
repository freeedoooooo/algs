# 吃点好的 MVP 落地规划

## 摘要
- 目标：验证产品最核心的差异化亮点——「不用想，照着做」的高效烹饪闭环。
- 范围（极简核心闭环）：AI 一键推荐菜单 + 烹饪前强制 Checklist + 多线程时间轴导航（含悬浮倒计时与提醒）。
- 明确不做（留待 V2）：AI 拍照入库、库存扣减、临期预警、家庭共享、订阅消息推送。
- 技术栈：微信原生小程序（WXML/WXSS/JS）+ 微信云开发 CloudBase（云函数 / 云数据库 / 云存储）。
- AI：云函数调用通义千问（DashScope，与你现有沟通链路一致，HTTP 接入简单，有免费额度）；接口层做抽象，后续可平滑切换腾讯混元。

## 关键设计决策
- 菜谱来源采用「预置菜谱库 + AI 组合推荐」混合模式，而非每次纯 AI 生成：
  - 预置 20-30 道经典家常菜的 `recipes` 种子数据，`timelineSteps`/`checklist` 人工编排，保证质量与响应速度。
  - AI 只负责「按场景筛选（快手/简单/周末大菜）+ 时令，从库中组合出 2 菜 1 汤」，返回菜谱 ID 列表；命中库外需求时兜底返回默认组合。
  - 好处：秒级响应、成本可控、时间轴质量稳定，最契合 MVP 快速验证。
- 无库存依赖：推荐不读取库存，仅用场景 + 时令 + （可选）用户偏好，降低首版复杂度。
- Checklist 解锁逻辑纯前端状态管理，全部勾选后才激活「开始烹饪」按钮。
- 时间轴导航用前端定时器驱动，倒计时结束调用 `wx.vibrateLong` + `wx.createInnerAudioContext` 播报提醒。

## 阶段 0：准备与合规（前置，非编码）
- 微信公众平台注册小程序，完成名称查重（备选：开饭清单 / 好好吃饭·备菜助手）。
- 开通云开发环境，选「按量付费」，记录 env ID。
- 申请通义千问 DashScope API Key，确认免费额度。
- 商标预检（第 9 类 / 第 42 类）可并行推进，不阻塞开发。

## 阶段 1：项目骨架与登录
- 初始化小程序项目，建议目录结构：
  - `miniprogram/pages/`（index 推荐页、menu 菜单确认页、prep Checklist 页、cook 时间轴导航页）
  - `miniprogram/components/`（recipe-card、checklist-item、timeline-step、float-timer）
  - `miniprogram/utils/`（request、timer、format）
  - `miniprogram/app.js`（云开发初始化 `wx.cloud.init`）
  - `cloudfunctions/`（login、recommendMenu、getRecipeDetail）
- `app.js` 中 `wx.cloud.init({ env, traceUser: true })`。
- `login` 云函数：用 `cloud.getWXContext().OPENID` 静默获取 openid，写入 `users` 集合。

## 阶段 2：数据模型与种子菜谱
- 云数据库集合：
  - `recipes`：字段沿用 PRD 3.2 设计（name、tags、estimatedTime、ingredientsNeeded、checklist{tools,seasonings,mainIngredients}、timelineSteps[{time,action,type,timer}]），新增 `season`（时令月份数组）便于筛选。
  - `users`：openid、preferences（taste/allergies/excludeIngredients，MVP 可留空默认）。
  - `menus`（可选）：缓存每次推荐结果，便于「换一换」与回溯。
- 导入 20-30 道种子菜谱（覆盖快手/简单/周末大菜三类标签），用云开发控制台 JSON 批量导入或一次性 `seed` 云函数写入。

## 阶段 3：AI 推荐菜单
- `recommendMenu` 云函数：入参 `{ scene, month, preferences }`；
  - 查询 `recipes` 按 scene 标签 + season 过滤出候选池；
  - 组装 Prompt 调用通义千问，要求从候选池中选出 1 荤 1 素 1 汤（或 2 菜 1 汤）并返回结构化 JSON（菜谱名/ID）；
  - 用返回名称匹配 `recipes` 得到 ID 列表；匹配失败或超时时兜底返回候选池随机合规组合。
- 首页 index：场景筛选器 tabs + 「今日推荐」按钮 + 推荐结果卡片列表；menu 页支持「换一换」（重新调用或从候选池重排）。
- 云函数中通过 `got`/`axios` 请求 DashScope 兼容 OpenAI 接口，API Key 存云函数环境变量，不硬编码。

## 阶段 4：烹饪前 Checklist
- prep 页：进入时调 `getRecipeDetail` 拉取所选菜谱的 `checklist` 与 `ingredientsNeeded`。
- 分三类渲染：【主料/配料】【调料】【工具】，用 `checklist-item` 组件管理勾选状态。
- 全部勾选后解锁「开始烹饪」按钮，跳转 cook 页并携带菜谱数据。

## 阶段 5：多线程时间轴导航（核心亮点）
- cook 页：按 `timelineSteps` 渲染时间轴，区分 prep/cook 类型样式，体现并行任务。
- 关键节点：为含 `timer` 的步骤启动独立倒计时，用 `float-timer` 悬浮组件显示剩余时间。
- 到点提醒：`wx.vibrateLong()` + `wx.createInnerAudioContext` 播放提示音/语音；支持一键「全部完成」。
- 定时器逻辑封装在 `utils/timer.js`，页面卸载时统一清理避免泄漏。

## 阶段 6：联调、体验版与灰度
- 真机预览 + 云函数日志排查；重点验证推荐响应时长、倒计时准确性、提醒触达。
- 上传体验版，小范围（家人/新手用户）试用，收集「是否真的不慌」的核心反馈。
- 根据反馈决定是否进入 V2（拍照入库 / 库存 / 家庭共享 / 订阅消息）。

## 验证方式
- 每阶段完成后真机自测对应闭环：阶段 3 能出菜单、阶段 4 能解锁、阶段 5 能倒计时提醒。
- 云函数本地/云端联调，检查 `recommendMenu` 兜底逻辑在 AI 超时时的表现。

## 假设与说明
- 假设你已有微信小程序账号或可注册；env ID、API Key 由你在阶段 0 提供。
- 项目将新建于 `60-mvp/` 下（如 `60-mvp/miniprogram` 与 `60-mvp/cloudfunctions`）。
- 首版 UI 以功能可用为主，不追求视觉精细；订阅消息模板等合规项在 V2 引入临期预警时再申请。
- 若你希望改用腾讯混元或跨端框架，AI 接入层与前端框架可替换，其余阶段不变。
