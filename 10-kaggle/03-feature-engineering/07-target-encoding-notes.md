## 一、Target Encoding 核心原理

### 1.1 是什么

**用目标变量（y）的统计值替换类别特征。**

```
Zipcode = "90210" → 查表 → 这个 Zipcode 的平均 Rating = 4.2 → 替换
```

编码后列名不变，但值从字符串变成连续数（本质是平均 Rating）。

### 1.2 代码流程

```python
# 1. 数据划分（防止信息泄露）
X_encode = X.sample(frac=0.25)       # 25% 训练编码器
X_pretrain = X.drop(X_encode.index)  # 75% 用于模型训练

# 2. 训练编码器（在 25% 数据上计算每个类别的平均 Rating）
encoder = MEstimateEncoder(cols=["Zipcode"], m=5.0)
encoder.fit(X_encode, y_encode)

# 3. 编码（覆盖原列，列名不变，值变成平均 Rating）
X_train = encoder.transform(X_pretrain)
```

### 1.3 为什么要独立数据训练编码器

```
编码器和模型用同一份数据 → 双重过拟合
类比：翻译官和学生不能用同一本教材
```

## 二、平滑（Smoothing）

### 2.1 解决两个问题

| 问题 | 场景 | 后果 |
|---|---|---|
| **未知类别** | 测试集出现训练集没有的 Zipcode | 编码值 = NaN |
| **稀有类别** | 某 Zipcode 只出现 1 次 | 平均 = 那一个样本的值，不可靠 |

### 2.2 平滑公式

```
编码值 = w × 类别平均 + (1-w) × 全局平均

w = n / (n + m)
```

| 参数 | 含义 |
|---|---|
| `n` | 该类别出现次数 |
| `m` | 平滑因子（超参数） |

### 2.3 m 值的影响

| m 值 | 效果 | 适用场景 |
|---|---|---|
| **m 小**（如 1） | 权重快速趋向 1，更信任类别平均 | 数据量大、类别可靠 |
| **m 大**（如 100） | 权重缓慢趋向 1，更依赖全局平均 | 数据量小、怕过拟合 |

### 2.4 具体例子（m=10，全局平均=$20,000）

| 类别 | n | w | 类别平均 | 编码值 | 说明 |
|---|---|---|---|---|---|
| Toyota | 500 | 0.98 | $22,000 | $21,960 | 几乎用类别平均 |
| Mercury | 1 | 0.09 | $50,000 | $22,700 | 被拉回全局平均 |
| Tesla（未知） | 0 | 0 | — | $20,000 | 直接用全局平均 |

## 三、Zipcode 实战解读

### 3.1 为什么选 Zipcode

- 3000+ 类别 → One-Hot 维度爆炸
- 100 万+ 行数据 → 够分 25% 训练编码器

### 3.2 编码值分布图解读

```python
ax = sns.distplot(y, kde=False, norm_hist=True)       # 蓝色：Rating 分布
ax = sns.kdeplot(X_train.Zipcode, color='r', ax=ax)   # 红色：编码值分布
```

**两个分布形状相似的原因：**

编码值就是从 Rating 算出来的（每个 Zipcode 的平均 Rating），所以分布必然相似。

**这不是"Zipcode 能预测 Rating"的证据，而是"编码正确实现了"的验证。**

### 3.3 编码值分布与 Rating 分布的关系

| 观察 | 原因 |
|---|---|
| 红色曲线峰值和 Rating 峰值对齐 | 大部分样本在常见 Zipcode，其平均 Rating 接近全局峰值 |
| 红色曲线更平滑 | 稀有 Zipcode 被平滑拉向全局平均 |
| 红色曲线范围更窄 | 平滑效应压缩了极端值 |

## 四、Target Encoding vs One-Hot

### 4.1 选择策略

| 类别数 | 推荐 | 原因 |
|---|---|---|
| 2-10 | One-Hot | 维度爆炸可控，信息无损 |
| 10-50 | 看模型 | 树模型偏 Target，线性模型偏 One-Hot |
| 50+ | Target Encoding | One-Hot 维度灾难 |

### 4.2 核心区别

| | One-Hot | Target Encoding |
|---|---|---|
| **保留什么** | 类别身份（你是谁） | 类别与目标的关系（你的表现） |
| **丢失什么** | 类别与目标的关系（模型自己学） | 类别身份（不同类别可能编码值相同） |
| **过拟合风险** | 低 | 高（需独立数据训练） |
| **维度** | 类别数个 | 1 个 |

### 4.3 本质

- **One-Hot** = "这是 Toyota"（事实，让模型自己学关系）
- **Target Encoding** = "Toyota 平均卖 $22,000"（统计结论，提前给关系）

## 五、常见困惑澄清

### 5.1 编码后列名还是 Zipcode，值已经不是邮政编码了

```
编码前：X_train.Zipcode = "90210"（字符串）
编码后：X_train.Zipcode = 4.2（浮点数，本质是平均 Rating）
```

列名没变，但含义变了。是 `encoder.transform()` 这行覆盖的。

### 5.2 缺失的是什么？

**不是 Rating 缺失，而是编码器不认识的新 Zipcode。**

```
编码器没见过 Zipcode=99999 → 编码值 = NaN → 用全局平均填充
```

### 5.3 为什么编码值分布和 Rating 分布相似？

**数学必然，不是巧合。**

```
编码值 = f(Rating)  →  分布必然相似
```

真正要看的是：模型用这个编码后，预测效果是否提升。

## 六、一页速记

| 困惑 | 澄清 |
|------|------|
| Target Encoding 用什么算编码值？ | 用目标变量 y（如 Rating）的平均值 |
| 为什么要独立数据训练编码器？ | 防止信息泄露，避免双重过拟合 |
| 平滑解决什么问题？ | 未知类别和稀有类别的过拟合 |
| m 值大还是小好？ | 看数据量：大数据用小 m，小数据用大 m |
| 编码后列名没变，值变了吗？ | 变了，从类别字符串变成平均 Rating |
| 编码值分布和 Rating 相似说明什么？ | 说明编码正确实现了，不是预测能力的证据 |
| Target 和 One-Hot 怎么选？ | 类别少用 One-Hot，类别多用 Target，还要看模型类型 |
| 缺失的是什么？ | 编码器不认识的新类别，不是目标变量缺失 |
