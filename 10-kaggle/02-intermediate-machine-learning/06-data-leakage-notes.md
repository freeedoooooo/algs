# 数据泄漏：分数虚高的元凶

> 来源：Kaggle《Intermediate Machine Learning》课程精华
> 覆盖：Data Leakage

---

## 一、什么是数据泄漏

**训练时用到了"实际预测时不可能拿到"的信息**，导致本地验证分数高得离谱，一上线/一提交真实分数就崩。

泄漏的模型不是学得好，是**作弊了**。

---

## 二、两种泄漏

### 类型 1：目标泄漏（Target Leakage）

某个特征**本身就是目标的结果**，或与目标共享同一个因果下游。

**经典例子：预测肺炎患者是否需要抗生素**

- 数据里有个特征 `took_antibiotics`（是否服用了抗生素）
- 用它预测，准确率 99%！
- 但实际上：**医生先确诊了才开抗生素**——这个特征是"知道答案之后"才产生的
- 真实场景中，预测时刻根本拿不到这个特征

**识别特征**：一个特征的重要性高得反常，且它的时间顺序发生在目标"之后"。

其他例子：
- 用"用户是否退款"预测"用户是否投诉"（退款往往发生在投诉之后）
- 课程实验里用"该数据集的行数"当特征（`Count` feature）——训练时它和目标的模式被记住了，测试时行数变了就失灵

### 类型 2：训练-测试污染（Train-Test Contamination）

预处理环节把测试集的信息混进了训练过程。

**典型错误：**

```python
# 错误：在全量数据（含测试集）上做归一化/填充/编码
scaler.fit(pd.concat([X_train, X_test]))       # 测试集的均值参与了！
imputer.fit(pd.concat([X_train, X_test]))      # 测试集的缺失分布参与了！

# 正确：只用训练集 fit，测试集只 transform
scaler.fit(X_train)
X_train_scaled = scaler.transform(X_train)
X_test_scaled = scaler.transform(X_test)
```

之前 target encoding 笔记里的教训是同一件事：**encoder 必须在训练集上 fit、在验证集上 transform**，否则验证分数虚高。

**Pipeline 天然免疫这种污染**——`my_pipeline.fit(X_train, y)` 时预处理器只在训练数据上学习参数，predict 时只套用、不再学习。这也是 03 课推荐 Pipeline 的深层原因。

## 三、如何发现和防范

### 3.1 发现

| 信号 | 说明 |
|---|---|
| 验证分数好得不真实 | 准确率突然 99%、MAE 骤降一个数量级 → 先怀疑泄漏，别急着高兴 |
| 特征重要性反常 | 某个业务上"不该这么强"的特征排第一 |
| 本地好、提交差 | Kaggle 排行榜分数远低于本地验证分 |

**检查方法**：打印 `model.feature_importances_`，对排名靠前的每个特征问一句——"**在真实预测的那一刻，这个值能拿到吗？它是不是目标发生之后才产生的？**"

### 3.2 防范清单

1. 理解数据的**生成过程和时间顺序**（什么先发生、什么后发生）
2. 剔除"结果类"特征（发生在目标之后的字段）
3. 预处理严格 fit/transform 分离，或直接用 Pipeline
4. 交叉验证时确保每折内部独立做预处理（Pipeline + cross_val_score 自动满足）

---

## 四、一句话总结

**数据泄漏 = 训练时用了预测时刻拿不到的信息（目标泄漏）或让测试集信息污染了训练（预处理污染）；分数好得不真实时先怀疑泄漏；防范靠理解数据的时间因果 + 严格的 fit/transform 分离（Pipeline 自动保证）。**
