# CV vs LLM 学习路径选择：思考总结

> 日期：2026-10-30  
> 主题：大语言模型 vs 计算机视觉领域的学习成本、稳定性与发展前景分析

---

## 一、核心问题

**LLM 是否已经成熟到成为红海？是否应该转向 CV 领域（如 OCR）解决特定细分问题？**

---

## 二、LLM 现状分析

### 2.1 LLM 确实卷，但"成熟"谈不上

大模型仍有大量未解问题：
- 推理成本高
- 幻觉问题
- 垂直领域微调困难
- Agent 工程化落地复杂

**但"从头训练通用大模型"确实是红海——那是巨头的游戏。**

### 2.2 LLM 应用层的问题

- 需求爆发但**同质化严重**
- 会调 API、会搭 RAG 的人越来越多
- 纯工程岗位的溢价在快速下降
- 范式极不稳定，今天的 RAG/Agent 框架两年后可能完全不同

---

## 三、CV 细分领域的机会

### 3.1 OCR 本身也卷了

传统 OCR（PaddleOCR、Tesseract 等开源方案）已经非常成熟，**纯做 OCR 引擎很难有差异化**。

### 3.2 但特定场景的文档理解仍有空间

- 医疗单据
- 工业铭牌
- 手写体识别
- 多语言混合排版
- **LLM + OCR 结合的方向**

### 3.3 CV 的优势

1. **落地闭环短**：工业质检、医学影像、缺陷检测等场景，客户要的是解决方案而不是通用模型
2. **数据壁垒 + 领域知识 = 护城河**：比纯算法竞赛更有商业价值
3. **趋势是 LLM + CV 融合**：多模态、视觉 grounding、文档理解等交叉地带是蓝海

### 3.4 建议

**选一个数据获取有门槛的垂直领域**（工业、医疗、农业），而不是选一个"算法已经公开"的通用任务。

> **算法本身不是壁垒，数据和场景理解才是。**

---

## 四、为什么不存在"一个模型解决所有问题"的 OCR

### 4.1 OCR 本质上是感知 + 理解的两阶段任务

1. **感知层**：从图像里识别出文字（检测 + 识别，即 where 和 what）
2. **理解层**：理解文字的结构、语义、上下文关系

### 4.2 感知层高度依赖场景分布

- 印刷体 vs 手写体，特征分布完全不同
- 中文 vs 阿拉伯文 vs 混合排版，字符集和排列规则不同
- 清晰扫描件 vs 手机拍照（歪斜、反光、阴影），图像质量差异巨大
- 表格、发票、医疗单据，**版式结构**完全不同

### 4.3 当前主流架构：基座 + 微调

```
┌─────────────────────────────────────────┐
│         场景特化层（LoRA / Prompt /       │
│         后处理规则 / 领域知识图谱)         │
├─────────────────────────────────────────┤
│      通用文档理解基座模型                   │
│   (LayoutLM / Donut / GOT-OCR 等)        │
│   能力：版面分析 + 文字识别 + 结构理解      │
├─────────────────────────────────────────┤
│      视觉编码器 + 语言模型                  │
│   (ResNet/SwIn + Transformer)            │
│   能力：特征提取 + 序列建模                  │
└─────────────────────────────────────────┘
```

**底层是通用的，越往上越需要针对场景做适配**——这和大模型的"基座模型 + 领域微调"范式一模一样。

### 4.4 OCR 的"最后一公里"往往不是模型问题

大模型微调完基本就能用了，但 OCR 落地时，**后处理规则**经常占一半工作量：

- 医疗单据：金额字段需要校验逻辑（不能把 0 识别成 O）
- 发票：需要和税务系统的规则对齐
- 工业铭牌：需要处理反光、磨损、特殊字体

> **商业价值恰恰在"微调 + 工程化"的环节，而不是基座模型本身。**

## 五、多模态大模型 vs 专用 CV 模型

### 5.1 核心认知

**多模态大模型"能读图" ≠ "能替代 CV"**

这就像"GPT-4 能写代码" ≠ "能替代专业编译器"——**通用能力和专用能力是两个维度**。

### 5.2 两类场景的本质差异

```
┌────────────────────────────────────────────────────────┐
│  场景复杂度 vs 模型选择                                    │
├────────────────────────────────────────────────────────┤
│                                                         │
│  简单文档 OCR           多模态 LLM 可以胜任              │
│  ├─ 清晰扫描件           (GPT-4o, Gemini, Qwen-VL)      │
│  ├─ 标准印刷体                                              │
│  └─ 规整排版                                                  │
│                                                         │
│  ──────────────── 分水线 ───────────────                │
│                                                         │
│  复杂/专业场景          必须用专用 CV 模型                │
│  ├─ 工业质检（微米级缺陷检测)                              │
│  ├─ 医疗影像（CT/MRI 病灶分割)                            │
│  ├─ 手写体识别（笔迹差异巨大)                             │
│  ├─ 实时视频流处理（毫秒级响应)                           │
│  └─ 边缘设备部署（手机/摄像头/嵌入式)                     │
│                                                         │
└────────────────────────────────────────────────────────┘
```

### 5.3 为什么复杂场景 LLM 搞不定？三个硬约束

#### 约束 1：精度要求（99.9% vs 95%）

| 场景 | 容错率 | 后果 |
|------|--------|------|
| 读一份菜单 | 错一两个字能猜出来 | 无所谓 |
| 医疗单据金额识别 | 0 和 O 搞错 = 金额错误 | 赔钱/合规风险 |
| 工业缺陷检测 | 漏检 = 不良品流出 | 召回/安全事故 |
| 车牌识别 | 错一位 = 套牌/逃逸 | 法律责任 |

**多模态 LLM 的本质是"概率生成"，它没有"确定性保证"这个概念。** 工业场景要的不是"大概率对"，是"必须对，错了能追溯"。

#### 约束 2：性能要求（毫秒级 vs 秒级）

```
工业产线节拍：每个产品检测时间 < 50ms
                 ↓
          模型推理必须 < 20ms
                 ↓
    只能用轻量级专用模型（MobileNet/YOLO-tiny)
                 ↓
    70B 参数的多模态大模型？想都别想
```

多模态 LLM 一次推理可能要几秒到十几秒，**在实时场景下根本不可用**。而一个 YOLO 模型在边缘设备上跑一次只要几毫秒。

#### 约束 3：成本要求

| 方案 | 单次推理成本 | 日处理量 100 万次 |
|------|--------------|-------------------|
| GPT-4o API | ~$0.01/次 | ~$10,000/天 |
| 自部署专用 CV 模型 | ~$0.0001/次 | ~$100/天 |

**差 100 倍。** 工业场景是大规模重复任务，用 LLM API 做 OCR 就像用出租车送外卖——能送，但亏死。

### 5.4 真正的格局：协作而非替代

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│   多模态 LLM                                        │
│   ├─ 优势：通用性强、零样本能力、理解语义上下文       │
│   ├─ 适合：一次性任务、复杂理解、人机交互            │
│   └─ 定位：大脑皮层 — 高级认知                       │
│                                                     │
│   专用 CV 模型                                       │
│   ├─ 优势：精度极致、速度极致、成本极致              │
│   ├─ 适合：规模化重复任务、实时场景、边缘部署        │
│   └─ 定位：小脑 — 精准运动控制                       │
│                                                     │
│   未来趋势：两者协作，不是替代                        │
│   └─ CV 做感知（检测/识别/分割)                      │
│   └─ LLM 做理解（语义/推理/交互)                     │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 5.5 具体例子：医院病历数字化

```
步骤 1：专用 CV 模型
  ├─ 版面分析（标题/段落/表格/图片区域检测)
  ├─ 文字识别（印刷体 + 医生手写体)
  └─ 表格结构提取（行列关系)
  
步骤 2：多模态 LLM
  ├─ 理解医学术语上下文（"CAD" 是冠心病还是计算机辅助设计?)
  ├─ 信息结构化抽取（诊断结果、用药方案、过敏史)
  └─ 生成结构化病历摘要
```

**CV 做"眼睛"，LLM 做"大脑"——这才是正确的分工。**

## 六、学习成本对比

### 6.1 总体对比

| 维度 | OCR / CV | LLM 方向 |
|------|----------|----------|
| **数学门槛** | 线性代数 + 概率统计够用，卷积/Transformer 直观可解释 | 需要更深概率论、优化理论、信息论理解 |
| **入门路径** | 清晰：传统图像处理 → CNN → 检测识别 → 文档理解，每一步都有明确产出 | 模糊：概念迭代极快，今天学的 prompt engineering 明天可能就被新范式取代 |
| **算力需求** | 低。单张 GPU 就能跑通 PaddleOCR、微调小型 CV 模型 | 高。微调一个 7B 模型至少需要 A100/多卡，推理部署也吃资源 |
| **数据获取** | 容易。开源数据集多，文档自己就能造，标注成本低（框+文字） | 难。高质量文本数据越来越稀缺，标注成本高 |
| **工程化难度** | 中等。主要是图像预处理、后处理规则、部署优化 | 高。RAG、Agent、向量数据库、推理加速，每一块都是深坑 |
| **从入门到能落地** | ~3-6 个月 | ~6-12 个月（且持续追赶新概念） |

**结论：OCR/CV 的学习成本明显更低。** 路径确定、算力便宜、反馈循环短。

### 6.2 分阶段对比

#### 入门阶段：CV 确实更友好

| 维度 | CV | LLM |
|------|-----|------|
| **直觉性** | 强。图像结果肉眼可见，对错一目了然 | 弱。损失曲线、注意力权重、生成质量都抽象 |
| **最小可运行示例** | 简单。用 YOLO 跑目标检测，几十行代码就能看到框 | 复杂。要配 tokenizer、加载模型、处理 KV cache |
| **数学门槛** | 线性代数 + 基础微积分够用 | 概率论、信息论、优化理论都要懂一些 |
| **算力需求** | 单 GPU 甚至 CPU 就能入门 | 没有 GPU 基本跑不动有意义的实验 |
| **调试体验** | 可视化损失图、看检测框，容易定位问题 | 生成质量差时，很难判断是数据/prompt/架构问题 |

**入门到"能跑通一个项目"：CV 大约 1-2 个月，LLM 大约 3-6 个月。**

#### 中级阶段：差距开始缩小

当你不再只是"调包"，而是要**理解原理并改进模型**时：

**CV 的难点开始浮现：**
- 数据增强策略（不同场景需要不同的增强 pipeline）
- 模型结构设计（为什么用 FPN？为什么用 Deformable Conv?）
- 损失函数设计（Focal Loss、Dice Loss 的适用场景）
- 多尺度/多任务学习（怎么平衡不同尺度的特征）
- 部署优化（量化、剪枝、蒸馏，工程量大）

**LLM 的难点也在浮现：**
- 分布式训练（DeepSpeed、Megatron，门槛极高）
- RLHF/DPO 对齐（调参像玄学）
- 长上下文处理（RoPE 外推、KV cache 优化）
- 推理加速（vLLM、TensorRT-LLM，工程复杂）
- 评估体系（怎么判断模型"变好了"本身就是难题）

**中级阶段两者难度相当，只是难点不同：CV 难在"数据+工程"，LLM 难在"系统+调参"。**

#### 高级阶段：LLM 的学习曲线更陡峭

到了前沿研究级别：

- **CV** 的前沿问题相对**聚焦**（新架构、新任务、新场景），一个博士组可以深耕一个方向几年。
- **LLM** 的前沿问题**极度发散**（架构、训练方法、对齐、安全、多模态、Agent、推理时计算...），每隔几个月就有范式级变化，**追新概念的成本极高**。

### 6.3 关键差异：反馈循环

```
CV 的反馈循环：
  改代码 → 跑训练 → 看可视化结果 → 知道哪里错了 → 再改
  （直观、快速、容易建立直觉)

LLM 的反馈循环：
  改代码 → 跑训练(贵) → 看生成样本 → 很难判断为什么变差/变好
  （抽象、慢、调参像炼丹)
```

**CV 的学习体验更像"学骑自行车"——摔了知道为什么摔。LLM 更像"学开飞机"——仪表盘太多，出问题了不知道看哪个。**

### 6.4 例外情况

- 如果你**数学基础很强**（概率论、线性代数、优化理论都熟），LLM 的学习曲线对你来说会平缓很多。
- 如果你**工程能力很强但不喜欢数学推导**，CV 更适合你——CV 的很多进步是靠"工程 trick"堆出来的（数据增强、训练技巧、部署优化）。

### 6.5 学习成本总结

| 阶段 | CV vs LLM 学习成本 |
|------|---------------------|
| 入门（能跑通项目） | **CV 明显更低** ⭐ |
| 中级（能改进模型） | 两者相当，难点不同 |
| 高级（能做前沿研究） | **LLM 更高**（概念迭代太快） |
| 长期维护知识 | **CV 更稳定**（卷积、Transformer 这些核心概念 10 年没大变） |

## 七、稳定性对比

### 7.1 技术本身会不会被替代？

- **OCR 作为独立任务**：有被多模态大模型"顺手解决"的风险。GPT-4o、Gemini 已经能直接读图理解文档了。纯 OCR 引擎的长期价值会缩水。
- **LLM 推理/Agent**：目前处于爆发期，但范式极不稳定。今天的 RAG 架构、Agent 框架，两年后可能完全不同。

### 7.2 岗位需求的稳定性

- **OCR/CV 落地场景**（工业质检、医疗影像、文档数字化）：这些是**实体经济的刚需**。工厂不会因为大模型进步了就不需要质检。数据壁垒 + 场景理解 = 长期护城河。
- **LLM 应用层**：需求爆发但**同质化严重**。会调 API、会搭 RAG 的人越来越多，纯工程岗位的溢价在快速下降。

### 7.3 稳定性排序

```
稳定性排序（从高到低）：

1. CV + 垂直场景（工业/医疗/农业）  ← 数据壁垒 + 实体经济需求
2. LLM + Agent 工程化落地          ← 需求大但迭代快，需要持续学习
3. 纯 OCR 引擎开发                 ← 被多模态模型替代风险高
4. 纯 LLM 微调/训练               ← 巨头的游戏，个人机会少
```

## 八、最优策略：交叉融合

### 8.1 核心思路

> **学 CV 的感知能力 + LLM 的理解能力，做"文档智能"这个交叉方向。**

### 8.2 具体架构

- **底层**：用 CV 做版面分析、文字检测识别（这是你的基本功）
- **上层**：用 LLM 做语义理解、信息抽取、问答（这是增值部分）
- **落地**：在具体场景（医疗单据、工业文档、法律文书）— 这是你的护城河

### 8.3 学习路径

1. **先掌握专用 CV 模型**（YOLO、PaddleOCR、分割模型）— 这是你的"硬技能"
2. **再学多模态融合**（怎么用 LLM 增强 CV 的输出）— 这是你的"差异化"
3. **深入一个垂直领域**（工业 or 医疗 or 文档）— 这是你的"护城河"

### 8.4 为什么这样选？

- 既有 CV 的稳定性，又不会被 LLM 浪潮甩开
- 学习路径清晰：先把 PaddleOCR / LayoutLM 跑通，再学多模态融合，每一步都有可交付的成果
- 纯靠 LLM 做 OCR 的人，永远只能在"简单场景"这个红海里卷
- 而你能做"复杂场景 + LLM 增强"，这就是你的不可替代性

---

## 九、最终结论

### 9.1 学习成本

**CV 的学习曲线更平缓、反馈更直观、知识更稳定。** 对于"想快速进入一个领域并建立长期竞争力"这个目标来说，CV 确实是性价比更高的选择。

### 9.2 稳定性

**越是需要"脏活累活"的场景（工业、医疗、边缘设备），越不容易被大模型替代，越有长期价值。**

### 9.3 发展策略

**最优策略是 CV 做底座 + LLM 做增强 + 垂直场景做护城河。** 不是二选一，而是以 CV 为主、LLM 为辅。

### 9.4 一句话总结

> **OCR/CV 入门快、落地稳，但纯做引擎没前途；LLM 天花板高但追概念累。选 CV 做底座 + LLM 做上层理解 + 垂直场景做护城河，是性价比最高的路。**

## 十一、能力向量的正交性分析框架

> 前面章节是经验判断，本章给它补上理论模型：把"能力"放进向量空间，用**正交性**来定义"不可替代价值"。

### 11.1 把能力拆成正交分量

设大模型能力向量为 **L**，你的能力向量为 **C**。把 C 分解成两部分：

```
C = C∥ + C⊥
    │      └─ 与 L 平行的分量  C∥ = (C·L / |L|²)·L
    └─ 与 L 正交的分量        C⊥，大小 = |C|·sinθ
```

- **C∥（平行分量）= 会被贬值的部分**。它与 L 同向，L 越长（大模型越强），这段就越冗余、越被覆盖。
- **C⊥（正交分量）= 护城河**。关键性质：**它的价值对 |L| 的增长免疫**——大模型再强，也投影不到你的正交方向上，侵蚀不了你。

> **不可替代价值 = |C|·sinθ。θ 越接近 90°，越安全。** 这就是"选正交方向"的数学依据。

### 11.2 陷阱一：L 不是静止的，它在旋转

"当前正交"不等于"永远正交"。多模态大模型（GPT-4o、Gemini、Qwen-VL）本质就是把 **L 朝 CV 轴旋转**。

- **脆弱正交**：只是"大模型现在还没学会"的方向（如通用图片描述）——L 一转过来就没了。
- **结构性正交**：概率生成模型*本质上*够不到的轴，无论多强、怎么转都到不了。这才是要押注的方向。

| 结构性正交的轴 | 为什么大模型转不过来 |
|---|---|
| 确定性 + 可追溯 | 它的本质是"概率生成"，要它"必须对、错了能查"是反其构造的 |
| 物理世界数据与实时控制 | 它活在数字/文本世界，够不到传感器、边缘设备、毫秒级闭环 |
| 边际成本结构 | 这是经济学轴，不是能力轴；大规模重复任务下差 100 倍 |
| 责任 / 合规 / 信任 | 谁签字、谁担责——人类社会的轴，模型无法承接 |
| 最后一公里领域工程 | 后处理规则、和旧系统/物理系统对接，是工程不是知识 |

### 11.3 陷阱二：纯正交 ≠ 有价值，还差第三根轴

能力空间里不止 L，还有**市场需求 D**。

```
理想位置：C ⊥ L（不可替代）  且  C·D 大（有人要）
失败位置：C ⊥ L  且  C·D ≈ 0（很独特，但没人需要 = 屠龙之技）
```

要的是：**正交于 LLM，但对齐实体经济刚需**（工业质检、医疗影像、文档数字化）。垂直场景正是同时保证了 ⊥L 和 ·D 大。

### 11.4 最优不是"纯正交"，而是"正交 + 能驾驭 L"

完全正交虽安全，却享受不到大模型红利（与 AI 进步脱钩）。真正的高手位置：

```
总价值   = |L + C|      ← 能把 L 当杠杆合成进来
独特贡献 = |C⊥|         ← 不可替代部分足够大
驾驭能力 = 保留一点 C∥   ← 懂得调用/编排 L，但不与它拼这段
```

即：**CV 做底座（大 C⊥）+ LLM 做上层增强（把 L 合成进来）+ 垂直场景做护城河（对齐 D）**。

### 11.5 落地：选方向时的三问

1. **θ 角**：它和大模型能力夹角多大？是"暂时不会"还是"本质够不到"？→ 只押结构性正交。
2. **旋转风险**：多模态/Agent 未来 2-3 年会不会把 L 转到这个方向？→ 避开会被扫到的。
3. **D 对齐**：有没有实体经济刚需在拉它？→ 没有需求的正交一文不值。

## 十二、推导一：为什么"调 API / 写 prompt / 搭基础 RAG"趋近于 0

这些技能的共同本质：都是"**如何操作 L、从 L 里榨出能力**"的薄薄一层，**长在 L 的方向上（C∥）**，是 L 的附属品。三股力量同时把它压向 0。

### 力量一：吸收（最本质）

Prompt 工程和基础 RAG，本质是"**对 L 的不完美做套利**"——赚的是"L 的能力"与"L 的默认表现"之间那道缝隙。**L 每变强一次，缝隙就缩小一次。**

| 你的技能 | 它套利的缝隙 | L 如何把缝隙吃掉 |
|---|---|---|
| Prompt 技巧 | 模型不听话、需引导 | RLHF 对齐、指令跟随、自我纠错 → 技巧变成默认行为 |
| 基础 RAG | 上下文短、知识旧 | 百万级长上下文、原生检索/记忆、Agent 自己会查 |
| 调 API / 胶水代码 | 模型不会自己编排 | Agent、function calling、MCP 标准、模型自己写工具调用 |

> **套利一个正在消失的缝隙，利润必然趋近于 0。**（the bitter lesson：能力被吸收进模型）

### 力量二：替代

你和 L 在**同一方向**上干活 = 替代品关系，**谁更长、更便宜，市场就用谁**。当 |L| 越来越大、成本越来越低，市场直接调用 L，不再付钱请你当"人肉桥梁"。

### 力量三：商品化

门槛低、不需要专有数据、不需要领域知识 → 人人可学 → 供给爆炸；同时需求又被力量一、二吸收 → **双杀**（对应"同质化严重、纯工程岗溢价快速下降"）。

### 澄清：不是"归零"，是"失去溢价"

```
有用 ≠ 有溢价
C∥ 依然要保留一点（得会驾驭 L）
但它的"不可替代性" → 0，从"护城河"降级为"入场券(table stakes)"
```

> **判断法则**：一个技能如果"人人几个月就能学会、且不依赖你独有的数据/场景/资质"，它就在 L 的方向上，早晚被压成入场券。

## 十三、推导二：为什么"CV + 垂直场景"三个全中

先纠正一个粗糙说法：**"CV"不是一个整体。**

```
通用 CV / 纯 OCR 引擎    →  只中 0~1 个（会被多模态扫掉）
CV + 垂直场景（硬约束区）→  三个全中
```

**"全中"发生在交集上**：CV 的"硬约束感知能力" × 垂直场景的"专有数据 + 领域知识"。两半是**相互加强**，不是各自为战。

### ✅ 检验 1（θ 角：结构性正交）——由"CV 硬约束感知"提供

复杂场景要的是**确定性精度、毫秒级实时、边缘部署、极低边际成本**——这些是物理/工程约束，不是知识。大模型本质是概率生成，构造上给不了"必须对、错了可追溯"。→ **结构性正交，θ≈90°。**

### ✅ 检验 2（旋转风险）——由"垂直场景"提供两堵墙

多模态 L 确实在朝 CV 旋转（通用图片理解会被扫到），但撞到垂直场景会减速停住，因为两堵翻不过的墙：

- **墙 A：物理/经济墙。** 概率生成模型无论多大，都不会自动给你确定性保证、边缘毫秒延迟、$0.0001/次成本。这是范式属性，不是"再训练一下"能得到的。
- **墙 B：数据墙（最关键）。** L 在**互联网公开数据**上训练；而工厂产线缺陷图、医院带标注影像**不在互联网上**，被物理/组织/合规挡着。

> **L 无法旋转进它根本拿不到的数据。** 垂直场景的专有数据，就是把 CV 能力"锁死在正交方向"的锁。

### ✅ 检验 3（D 对齐）——由"垂直场景"提供

- **实体经济刚需**：工厂永远要质检，医院永远要读片；需求不因 AI 进步而消失，反而可能增长。
- **付费意愿**：解决具体痛点 = 清晰 ROI = 有人掏钱，与"通用能力被商品化、无人单独付费"相反。

### 相互加强：为什么是"乘法"而非"加法"

```
垂直场景
├─ 专有数据   → 锁住旋转风险（检验2 墙B）
├─ 领域知识   → 搞定"后处理/最后一公里"（结构性正交，检验1）
└─ 刚需+付费  → 对齐需求（检验3）

CV 硬约束感知
└─ 确定性/实时/低成本能力 → 结构性正交（检验1）

两者相乘 = 数据壁垒 × 硬约束能力 × 刚需 → 三个检验同时拉满
```

### 对照表：看清"全中"的边界

| 方向 | 检验1 θ角 | 检验2 旋转风险 | 检验3 D对齐 | 结论 |
|---|---|---|---|---|
| 纯通用 OCR 引擎 | ✗ 与多模态同向 | ✗ 正被扫 | △ 需求在但被商品化 | 只中 0~1 个 → 没前途 |
| 屠龙型 CV 冷门研究 | ✓ 很正交 | ✓ 转不过来 | ✗ 没人要 | 中 2 个 → 独特但无价值 |
| **CV + 垂直场景（硬约束区）** | **✓ 确定性/实时/成本** | **✓ 数据墙+物理墙** | **✓ 实体刚需+付费** | **三个全中 → 深耕** |

### 前提：安全区住在"交集"里，漂出去就失效

若在 CV 内部往"通用、互联网数据、非实时"一侧漂移（如通用图像描述），θ 角立刻变小、旋转风险升高——从"全中"滑回"纯 OCR 引擎"那一行。

> **精确建议**：不是"学 CV"，而是**待在 CV 的结构性正交边缘（硬约束感知）× 垂直场景的专有数据/领域知识**——这个交集才是"L 越长、你越值钱"的位置。

### 一条统一判断法则

> **你的能力要正交于"大模型的本质属性"（概率生成、数字世界、公开数据），同时对齐"实体世界的刚需与专有数据"。**
